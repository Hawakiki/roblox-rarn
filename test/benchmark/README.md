# test/benchmark — Wally 대 Rarn

레지스트리에 실재하는 패키지 **506개**(전이 포함 575개)로 두 도구를 같은 조건에서 돌린 기록.

```bash
bun run build
bun test/benchmark/bench.ts --sizes=10,50,150,506 --warm=3 --rarn="$PWD/dist/rarn.exe"
```

`bun test` 가 돌리지 않는다 — 네트워크가 필요하고, `wally` 가 있어야 하고, 몇 분 걸린다.
아래 숫자는 손으로 옮긴 것이고 측정한 기계를 함께 적는다.

---

## 결과

측정: Windows 11 / NTFS, Bun 1.3.14, Wally 0.3.2, 2026-08-22.
Rarn 은 **컴파일된 바이너리**(`dist/rarn.exe`)다 — `bun run src/cli.ts` 는 매번 244개 모듈을
트랜스파일하므로 컴파일된 Wally 와 비교할 물건이 아니다.

| 직접 의존 | rarn (콜드) | rarn (웜) | wally | rarn 파일 | wally 파일 | rarn 디스크 | wally 디스크 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 10 | 3.17 s | **284 ms** | 1.52 s | 174 | 938 | 0.6 MB | 2.3 MB |
| 50 | 8.23 s | **756 ms** | 2.32 s | 812 | 2045 | 3.5 MB | 9.7 MB |
| 150 | 21.33 s | **2.46 s** | 4.56 s | 3113 | 6951 | 13.1 MB | 46.3 MB |
| 506 | 37.31 s | **5.57 s** | 9.76 s | 7045 | 12956 | 43.3 MB | 107.9 MB |

**웜은 3회 중 좋은 쪽, 콜드는 1회.** 평균이 아니라 최선을 쓴다 — 알고 싶은 것은 도구가 낼 수
있는 값이지 그때 기계가 무엇을 하고 있었는가가 아니다.

세 열이 서로 다른 것을 말한다.

- **rarn 웜** — 락파일이 최신이고 캐시가 따뜻하다. **네트워크 요청 0회.**
- **rarn 콜드** — 캐시가 비었고 락파일이 없다. 해석과 다운로드를 전부 다시 한다.
- **wally** — Wally 에는 **아카이브 캐시가 없다.** 인덱스 클론만 캐시하므로 매 설치가 전부
  다시 받는다. 즉 이 열은 Wally 의 콜드이자 웜이다 — 나눌 것이 없다.

### Wally 의 첫 실행은 따로 잰다

Wally 는 인덱스 저장소를 통째로 git clone 한다. 한 번뿐이지만 공짜가 아니고, `git` 이 깔려
있어야 한다.

| | 10개 설치 |
|---|---:|
| 인덱스 없음 (기계에서 처음) | **12.1 s** |
| 인덱스 있음 | 1.52 s |

디스크에 **46 MB**. Rarn 은 HTTP 메타데이터만 쓰므로 이 비용도, git 의존성도 없다.

### 그래서 무엇이 빠른가

| | rarn | wally |
|---|---|---|
| 반복 설치 (CI, 브랜치 전환, 협업자 합류) | **5.6 s** — 네트워크 0 | 9.8 s — 575개 전부 다시 받음 |
| 기계에서 처음 | 37.3 s | 9.8 s + 인덱스 클론 12 s |
| 인덱스 클론 이후의 첫 설치 | 37.3 s | 9.8 s |

**콜드에서는 Wally 가 빠르다.** 인덱스가 로컬에 있으니 해석에 네트워크가 들지 않는다.
Rarn 은 575개 메타데이터를 HTTP 로 묻는다 — 506개 그래프에서 37.3 s 중 **8.9 s** 가 그것이다.
git clone 을 없앤 대가이고, 표에 그대로 적어 둔다.

거꾸로 **반복 설치는 Rarn 이 낫고 그쪽이 훨씬 자주 일어난다.** Wally 는 캐시가 없어 CI 가
돌 때마다 575개를 다시 받는다.

## 디스크: 파일 수가 요점이다

506개에서 **7,045 대 12,956 파일**, **43.3 대 107.9 MB**. 용량보다 파일 수가 중요한데,
Rojo 가 동기할 때 세는 것이 파일이고 Studio 가 여는 것도 파일이기 때문이다.

차이는 **설치 시점 가지치기**에서 온다. Wally 의 `unpack_into_path` 는 `archive.extract` 한 줄이라
zip 을 통째로 편다 — `docs/`, `CHANGELOG.md`, `selene.toml`, 벤더된 서브모듈까지. Rarn 은 패키지의
`default.project.json` 을 읽어 `$path` 가 가리키는 것만 복사한다.

## 그리고 그것이 correctness 차이가 된다

가지치기는 용량 얘기로 보이지만 아니다. **모듈 루트에 `init.luau` 가 있는가** — 즉 Rojo 없이
`require` 가 닿는가:

| | 모듈 폴더 | init 있음 | 비율 |
|---|---:|---:|---:|
| **rarn** | 556 | **548** | **98.6%** |
| wally | 575 | 148 | 25.7% |

Wally 설치본의 **74%** 는 모듈 루트에 `init` 이 없다. Wally 가 틀린 것이 아니라 설계가 그렇다 —
중첩된 프로젝트 파일을 **Rojo 가 동기 시점에 다시 해석**하는 것을 전제한다. 그래서 Wally 설치는
Rojo 가 있어야 뜻이 서고, Rarn 설치는 그렇지 않다.

**Wally 는 되는데 Rarn 만 안 되는 패키지: 0개.** Rarn 이 못 푸는 8개(1.4%)는 프로젝트 파일을
해석하지 못해 전체 복사로 물러난 경우이고, 그때 나오는 트리는 **Wally 가 항상 내는 것과 같다.**
설치 때 이렇게 말한다:

```
note @nightcycle/midas@6.1.8: default.project.json uses node_modules, which Rarn does not interpret
note @ffrostflame/sourcemap@0.1.1: default.project.json has no usable "$path"
```

## 중복: 506개 규모에서 제약 1 이 유지되는가

```
rarn  _Index 엔트리 574 (+ server realm 1)   같은 패키지가 두 버전으로 설치된 것: 0
wally _Index 엔트리 575                       같은 패키지가 두 버전으로 설치된 것: 0
```

둘 다 0 이다. 제약 1 이 금지하는 호환 중복은 어느 쪽에도 없다.

## 세트를 어떻게 골랐나

임의로 고르면 벤치마크가 아니라 일화가 된다. 순서와 근거:

| 단계 | 남은 수 | 근거 |
|---|---:|---|
| `wally-index` 의 전체 패키지 | 7,226 | `git clone --depth 1` |
| 최신 버전 · 프리릴리스 제외 | 5,489 | 프리릴리스는 opt-in 이라 기본 해석에 안 들어온다 |
| `realm = "shared"` | 5,224 | realm 이 섞이면 배치 규칙이 변수로 들어온다 |
| 피의존 횟수 상위 | 600 | **실제로 쓰이는 것**을 재려고. 인덱스의 5,810개 의존 엣지로 셈 |
| 인덱스만으로 폐포가 닫히는 것 | 577 | 전이 의존 하나라도 인덱스에 없으면 제외 |
| API 에 실재 (650개 이름 전수 확인) | 577 | 인덱스에는 있는데 API 가 404 인 것이 있다 |
| **합동 해석되는 것** | **506** | 71개 제외 — 아래 |

**71개는 서로 양립하지 않아서 뺐다.** 예: `csqrl/sift` 를 두 패키지가 `>=0.0.8 <0.0.9` 로
묶는데 직접 의존은 `^0.0.11` 이다. 0.x 에서 patch 가 다르면 Cargo/Wally 규칙상 호환이 아니다.
Rarn 은 이것을 `RN0200` 으로 정확히 보고한다 — 벤치마크에서 뺀 이유는 버그라서가 아니라
**두 도구가 설치에 성공해야 시간을 비교할 수 있어서**다.

고른 결과는 `packages.json` 에 박아 두었다. 재현 가능해야 하므로 매번 다시 고르지 않는다.

### 별칭 다섯 개는 손으로 풀었다 (RN-16)

506개 중 다섯 쌍이 **대소문자만 다른 별칭**을 갖고 있었다 — `TableUtil` 대 `Tableutil`,
`EnumList` 대 `Enumlist` 같은 것들. Windows 와 기본 macOS 볼륨에서 그것은 한 파일이므로
**이 벤치마크는 그동안 다섯 패키지가 서로 덮어쓰는 설치를 재고 있었다.** 정확히 그것이
RN-16 이고, `link` 이 shim 1,136개를 썼다고 보고하는데 디스크에 1,131개가 있던 이유다.

규칙은 하나다: **파일 순서상 먼저 나온 쪽이 별칭을 지키고, 뒤에 나온 쪽이 자기 scope 를
PascalCase 로 앞에 붙인다.** 결정적이라 다시 만들어도 같은 답이 나온다.

| 패키지 | 전 | 후 |
|---|---|---|
| `finobinos/tableutil` | `Tableutil` | `FinobinosTableutil` |
| `sleitnick/enum-list` | `EnumList` | `SleitnickEnumList` |
| `howmanysmall/better-signal` | `BetterSignal` | `HowmanysmallBetterSignal` |
| `kineticwallet/lemon-signal` | `LemonSignal` | `KineticwalletLemonSignal` |
| `farukcoskn/waitfor` | `Waitfor` | `FarukcosknWaitfor` |

**이 표의 시간들은 수정 전에 측정된 것이다.** 다섯 shim 이 더 써지므로 7,045 파일이
7,050 이 되고, 그 차이는 잰 시간의 0.1% 미만이다 — 다시 재기 전까지는 그렇게 읽어야 한다.

## 두 매니페스트가 같은 것을 말하게 하기

가장 조용히 틀릴 수 있는 자리다. **Wally 는 Cargo 문법이라 맨 `1.2.3` 이 `^1.2.3` 이고,
`rarn.json` 은 npm 문법이라 같은 글자가 정확 핀이다.** 그래서 양쪽 다 `^` 를 명시해서 쓴다.

```toml
Signal = "sleitnick/signal@^2.0.3"
```
```json
{ "@sleitnick/signal": "^2.0.3" }
```

그 밖에:

- **Rarn 의 캐시를 `RARN_CACHE_DIR` 로 임시 경로에 돌린다.** 콜드가 진짜 콜드가 되고,
  개발자의 진짜 캐시를 건드리지 않는다.
- **Wally 의 인덱스 클론은 건드리지 않는다.** 일회성 비용을 매 회차에 물리면 다른 것을 재게
  된다. 위에 따로 한 번 쟀다.
- 두 매니페스트 모두 같은 `place` 를 선언한다. 안 하면 크로스 realm 링크가 필요할 때
  `RN0031` 로 멈춘다.

## 이 벤치마크가 찾아낸 것

만드는 도중에 출하된 결함 두 개가 나왔다. 둘 다 소규모 트리에서는 보이지 않는다.

**512 KiB 넘는 파일이 든 패키지를 설치할 수 없었다** (RN-6). fflate 의 비동기 `unzip` 이
그 크기를 넘는 엔트리를 워커에 넘기는데 Bun 에서 그 워커가 아무것도 돌려주지 않는다. Node 에서는
멀쩡하다. `4x8matrix/class-index@3.0.0` 은 2.7 MB API 덤프를 담고 있어 **어떤 Rarn 으로도**
설치되지 않았고 `wally install` 은 됐다. 증상은 "the download may be corrupt. Try again" 이었는데
아카이브는 멀쩡해서 다시 받아도 달라질 것이 없었다.

**해석이 그래프가 넓을수록 느려졌다.** 메타데이터를 라운드마다 무제한 `Promise.all` 로 던져
직접 의존 506개면 소켓 506개를 같은 순간에 열었다. 라이브 레지스트리, 150개 기준:

```
 8 -> 5.0s    16 -> 2.8s    32 -> 1.8s    64 -> 7.4s    무제한 -> 21.9s
```

절벽이지 경사가 아니고 무제한은 그 반대편 끝에 있었다. 32 로 묶어 506개 그래프의 해석이
**44.8 s → 8.9 s** 가 됐다. 위 표는 두 수정이 들어간 뒤의 숫자다.

## 하니스가 이 규모에서 보이는 한계

`tests/roblox/verify.luau` 를 506개 트리에 돌리면 1,909개 중 1,794개가 통과한다. 남는 115개는
Rarn 의 결함이 아니라 하니스가 **별칭 이름으로 동일성을 비교**하기 때문이다.

40개 별칭이 둘 이상의 패키지를 가리킨다 — 스코프가 1,495개인 레지스트리에서 `React`,
`Signal`, `Janitor` 같은 이름은 여러 사람이 쓴다.

```
React:  jsdotlua_react@17.2.1  ,  haedrix_react@17.3.10
```

이 둘이 다른 인스턴스인 것은 **맞는** 동작인데 하니스는 실패로 적는다. 손으로 만든 작은
트리에서는 별칭 하나가 패키지 하나였으므로 드러나지 않던 전제다. 나머지는 위에 적은
가지치기 폴백 8건이다.
