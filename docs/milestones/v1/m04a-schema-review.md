# M4a — 스키마 동결 리뷰 (지금 할 수 있는 것)

> 완료 시점의 사실만 담고 이후 편집하지 않는다 — 링크 수정만 예외.

**완료:** 2026-08-22
**결과:** 안건 넷을 결론냈고, 읽는 도중에 **출하된 결함 하나**가 나와 고쳤다.
필드 설명문에 "왜 이 모양인지"를 넣었다. 동결 선언은 M4b 로.

---

## 왜 둘로 쪼갰나

M4 는 앞의 셋과 판단의 성질이 다르다.

| | 판단 기준 | 틀리면 |
|---|---|---|
| M1 | 서버가 받나 | 서버가 알려준다 |
| M2 | 두 shim 이 같은 경로에 오나 | 파일 시스템이 알려준다 |
| M3 | 출력·트리가 같나 | `diff` 가 알려준다 |
| **M4** | **이 필드가 앞으로도 맞나** | **아무도 안 알려준다** |

M1~M3 는 전부 측정으로 닫혔다. M4 는 측정할 대상이 미래라 같은 방법이 안 통한다. 그래서
**지금 증거로 정할 수 있는 것(M4a)** 과 **사용자만 알려줄 수 있는 것(M4b)** 을 갈랐다.

## 읽다가 나온 결함 — 생성된 Luau 가 파싱되지 않는다

`dataModelPath` 의 패턴이 `^game(\.[A-Za-z_][A-Za-z0-9_]*)+$` 였다. 세그먼트마다 Luau
식별자를 요구한다. **그런데 Rojo 인스턴스 이름에는 그런 제약이 없다.**

`place` 는 선언하지 않으면 프로젝트 파일에서 파생되므로, 이름을 정하는 것은 우리가 아니라
사용자의 `default.project.json` 이다. 재현:

```json
"ReplicatedStorage": { "My Packages": { "$path": "RARN_MODULE" } }
```

```lua
-- 설치 성공, 트리 정상, 그리고 이 파일:
return require(game.ReplicatedStorage.My Packages._Index["evaera_promise@4.0.0"]["promise"])
```

**Luau 가 아니다.** 설치는 초록색으로 끝나고 Studio 에서만 터진다 — CLAUDE.md 가 적어 둔
*"A wrong `place` fails with nothing useful"* 의 한 종류다.

고침은 렌더링 쪽이다. 경로는 사람이 말하는 방식대로 점으로 구분해서 쓰고, shim 을 만들 때
**점이 닿지 못하는 세그먼트만** 대괄호로 감싼다:

```lua
return require(game.ReplicatedStorage["My Packages"]._Index["evaera_promise@4.0.0"]["promise"])
```

필요한 것만 감싼다. 흔한 경로는 그대로 `game.ReplicatedStorage.Packages` 로 읽힌다.
스키마 패턴도 함께 풀었다 — 이제 `[`·`]`·`"` 만 거부한다. 그것들은 입력이 아니라 출력 문법이다.

## 안건 넷

**`registry` 가 두 뜻인 것.** 이미 옳고 이미 문서화돼 있었다. 락파일 최상위는 API 베이스,
`root.registry` 는 인덱스 저장소이고 스키마가 그 구분을 명시한다. 코드도 확인했다 —
`freshness.ts` 가 `lockfile.root.registry` 를 매니페스트의 `registry` 와 비교한다. **바꿀 것 없음.**

**`place` 에 dev 가 없는 것.** 맞다. 배치는 가장 넓은 요구자로 정해지므로 dev 에 놓인 패키지는
dev 요구자만 가질 수 있다 — 더 넓은 것이 있었다면 배치가 넓어졌을 것이다. 즉 **dev 로 건너갈
일이 없다.**

다만 그 사실이 주석에만 있었고 타입은 `Placement` 전체를 받고 있었다. `dev` 가 들어오면
조용히 `serverPackages` 를 써서 **엉뚱한 서비스를 가리키는 shim** 이 나온다. 오늘 도달
불가능한 것과 내일도 그런 것은 다르므로, 시그니처를 `Exclude<Placement, 'dev'>` 로 좁히고
`assertCrossable` 이 경계에서 검사하게 했다. 주석이 하던 말을 컴파일러와 에러가 하게 된다.

**`lockfileVersion` 을 1.0 에서 올릴 것인가.** 올리지 않는다. 이 번호는 **포맷**을 따르지
릴리스를 따르지 않는다. 의식으로 올리면 이미 디스크에 있는 모든 락파일을 아무 이유 없이
무효로 만들고, 다음 사람에게 "이 숫자는 버전 번호를 따라간다" 고 가르치게 된다. 깨는 변경이
필요해지면 그때 2 가 된다. 스키마 설명문에 그 규칙을 적었다.

**`exclude` 기본값.** M1 이 남긴 안건이고 #29 로 고쳤다. 여기서는 스키마 설명문이 한 줄이던
것을 채웠다 — 무엇이 이미 빠지는지, `include` 가 정확한 경로일 때만 그것을 뚫는 이유가
무엇인지, 그리고 발행이 되돌릴 수 없으므로 **틀리는 두 방향이 대칭이 아니라는** 것.

## 설명문에 "왜" 를 넣은 곳

| 필드 | 넣은 것 |
|---|---|
| `version` | 발행하면 영구다. 이 필드가 실수와 영영 못 쓰는 번호 사이의 유일한 것 |
| `packageDir` | 패턴은 경로의 *모양*만 본다. 대소문자를 무시하는 파일시스템에서 "Packages" 는 packages/ 이기도 하고, 그게 0.1.0 이 지운 것 |
| `place` | dev 필드가 없는 이유. 파생 규칙과, 두 프로젝트 파일이 갈리면 파생하지 않는 이유 |
| `aliases` | 유일성의 폭이 섹션이라는 것과, 506개 중 40개가 겹친다는 측정 |
| `include` | 정확한 경로만 기본 제외를 뚫는 이유 |
| `exclude` | 이미 빠지는 목록 전체와, 틀리는 두 방향의 비대칭 |
| `dataModelPath` | 세그먼트가 식별자가 아니어도 되는 이유, 대괄호는 쓰지 말라는 것 |
| `lockfileVersion` | 릴리스가 아니라 포맷을 따른다는 것 |

## M4b 로 넘긴 것

동결 선언 자체. 게이트가 열려야 한다 — 우리 밖 프로젝트 3~5개가 0.1.x 로 돌아가야 하고,
지금은 0명이다.

**게이트는 저절로 열리지 않는다.** 사용자가 0명인 상태로 가만히 있으면 영영 0명이다. M4b 는
시간이 아니라 행동을 기다린다.

그 사이에 쓸 수 있는 증거가 하나 있다 — **일부러 과하게 만든 테스트 게임.** 스키마 필드
대부분이 아직 진짜로 쓰인 적이 없다: `resolutions`, `aliases`, `place.serverPackages`,
`devDependencies`, `include`/`exclude`. 동결 전에 그것들을 실제로 써 보는 것보다 나은 것이 없고,
`test/roblox/` 가 지금 5 패키지짜리라 크게 만들면 영구 픽스처로도 남는다.

**그것으로 게이트가 닫히지는 않는다.** 우리가 만든 것은 우리다 — 도구의 가정을 아는 사람은
모르는 사람이 걸어들어갈 길을 무의식적으로 피해 간다. 게이트 문구가 "우리 밖" 인 이유가 그것이다.
