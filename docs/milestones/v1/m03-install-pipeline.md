# M3 — 파이프라인을 `cli/` 에서 꺼내기

> 완료 시점의 사실만 담고 이후 편집하지 않는다 — 링크 수정만 예외.

**완료:** 2026-08-22
**결과:** `src/install/run.ts` 가 파이프라인을 갖고, `src/cli/commands/install.ts` 는 배선만
남았다. 합성 테스트 8개가 생겼다. **행동 변화 0.**

---

## 무엇이 문제였나

`src/cli/commands/install.ts` 가 281줄에 import 23개였고, 그중 레이어 모듈이 12개였다.
파이프라인 전체가 CLI 명령 안에서 조립되고 있었다.

CLAUDE.md 의 레이어 표는 `cli` 에 비즈니스 로직을 금지하고, 같은 문서가 *"Anything worth
testing must be reachable without spawning the CLI"* 라고 적는다. 도달할 수 없었다 —
`src/cli.ts` 가 부르는 것 하나뿐이고 `tests/` 에서의 import 는 0건이었다.

**각 단계는 전부 테스트가 있었다. 없던 것은 배치였다.** 어느 단계가 어느 단계 앞에 오는지,
무엇을 무엇에게 넘기는지, 락파일을 언제 쓰는지. 이 프로젝트에서 가장 나빴던 결함이 정확히
거기 있었다 — RN-1 은 소유권 검사가 다운로드에 대해 *언제* 도느냐의 문제였지 어느 단계가
무엇을 하느냐의 문제가 아니었고, 그것을 붙잡을 테스트를 쓸 자리가 없었다.

## 어떻게 갈랐나

| | |
|---|---|
| `src/install/run.ts` | 읽기 · 신선도 · 해석 또는 재사용 · 가져오기 · place · 링크 · 락파일 · 결과 |
| `src/cli/commands/install.ts` | 스피너, verbose, 요약 렌더링, 종료 코드 |

**진행 상황은 `observer` 로 뒤집었다.** 파이프라인은 아무것도 출력하지 않고 무슨 일이
일어나는지만 알린다. 터미널이 없는 호출자 — 테스트, 또는 여러 프로젝트에 대해 이것을 돌리는
드라이버 — 가 특수한 경우가 아니라 그냥 호출자가 된다.

`store` 도 주입받는다. 테스트가 전역 캐시를 건드리지 않는다.

`registry` 는 기본값을 두지 않았다. 네트워크 클라이언트를 기본으로 갖는 것이 걷어내려던
결합 그 자체다 — 기본값은 CLI 가 채운다.

`add` · `remove` · `up` 은 그대로다. 셋 다 출력까지 원하므로 CLI 쪽 `install()` 을 계속
부르고, 그 시그니처는 바뀌지 않았다.

## 테스트 8개

| | 무엇을 붙잡나 |
|---|---|
| 읽기→해석→가져오기→가지치기→링크→기록 | 끝단 한 번. 락파일이 마지막에 쓰인다 |
| 단계 순서 | `resolving` → `fetching` → `linking` |
| 신선한 락파일은 해석을 건너뛴다 | **메타데이터 호출 0회** — 트리는 어느 쪽이든 같아서 이것 말고는 볼 방법이 없다 |
| 매니페스트가 바뀌면 다시 stale | 이유에 새 패키지 이름이 나온다 |
| `--frozen-lockfile` 은 거절한다 | 그리고 **아무것도 쓰지 않는다** |
| `--production` 은 부분집합 | 그리고 락파일을 쓰지 않는다 |
| 남의 디렉터리를 거절한다 | **가져오기 전에.** 소스 파일이 그대로 남아 있는지까지 |
| observer 없이도 돈다 | 선택적 훅이 전부 없어도 되는지 |

여덟 번째가 첫 번째만큼 중요하다. 파이프라인이 출력하지 않는다는 것이 깨지면 그 순간
테스트 러너 자신의 출력에 글자가 섞이기 시작한다 — 알아차리기에 그보다 나은 자리가 없다.

## 행동이 그대로인지

리팩터의 유일한 위험은 옮기다 순서를 바꿔 먹는 것이다. 실제 설치로 대조했다:

```
                옛 코드 (develop)          새 코드
installed 5 packages into RARN_MODULE, RARN_MODULE_SERVER   동일
  26 files, 7 links, 338 pruned                             동일
파일 트리 33개                                                동일
```

출력도 트리도 `diff` 가 비었다.

## 남긴 것

R2 §6.4 의 마지막 REDUCE_SCOPE 단계가 닫혔다. 워크스페이스를 짓게 된다면 그 드라이버가
파이프라인을 여러 멤버에 대해 돌려야 하는데, 이제 부를 수 있는 자리에 있다 — 짓는다는 뜻은
아니고, 짓지 못할 이유 하나가 사라졌다는 뜻이다.

그리고 M4(스키마 동결)가 기대는 것이 생겼다. 동결된 포맷을 지키는 것은 테스트이고, 그
포맷을 읽고 쓰는 경로가 이제 테스트 안에 있다.
