# M8 — `cli/` 에 남은 로직 감사

> 완료 시점의 사실만 담고 이후 편집하지 않는다 — 링크 수정만 예외.

**완료:** 2026-08-23
**결과:** 결함 2개(RN-14, RN-15). `rarn cache` 에 테스트가 생겼다(8개). 542 통과.

---

## 왜 했나

RN-8 은 다른 결함들과 종류가 달랐다. PLAN.md §3 이 그때 이렇게 적었다 —
**"못 잡은 게 아니라 안 본 것"**. `rarn init` 에는 테스트가 하나도 없었고, 두 결함 다
이국적이지 않았다. stdin 리다이렉트와 빈 디렉터리다.

그 문장이 아직 유효한지 재는 것이 이 마일스톤이다. 질문은 하나다:
**`cli/` 에 남아 있으면서 아무 테스트도 밟지 않는 행동이 또 있나?**

CLAUDE.md 는 `cli/` 가 "배선과 출력만" 이라고 적어 두었다. 그것이 사실이면 감사할 것이
없고, 사실이 아니면 사실이 아닌 곳이 정확히 위험한 곳이다.

## 아니었던 것들

감사의 절반은 아닌 것을 확인하는 일이었고, 넷은 실제로 아니었다. 추측이 아니라 밟아서
확인했으므로 여기 적는다 — 다음에 같은 의심이 들 때 다시 재지 않게.

| 의심 | 확인 방법 | 결과 |
|---|---|---|
| `up` 의 `candidates[0]` 이 최신이라고 가정한다 | `registry/parse.ts:32` 가 `semver.rcompare` 로 정렬 | **정렬은 파싱 계층이 보장한다.** 옳다 |
| `search` 의 `versions[0]` 은 정렬을 안 거친다 | 라이브 API 3개 비교 | **API 가 패키지당 정확히 1개, 최신을 준다.** 3/3 일치 |
| `dedupe` 가 찍는 `resolutions` JSON 을 붙여넣으면 안 맞는다 | `resolve.ts:293` 이 `@${name}` 으로 키를 만든다 | 매니페스트 형식과 같다. 옳다 |
| 파이프로 넘길 때 색 코드가 섞인다 | `od -c` 로 확인 | 0개. 단 **`FORCE_COLOR=3` 이 셸에 있으면 섞인다** — `output.ts` 주석이 경고한 그대로였고, 감사 중에 한 번 속았다 |

빈 디렉터리에서 read-only 명령 12개를 전부 돌린 것도 여기 속한다. 전부 `RN0010` 이나
`RN0700` 으로 정확히 실패했다 — RN-9 때 뚫렸던 자리는 막혀 있다.

## 결함 둘, 둘 다 `cache` 에

### RN-14 — 질문만 하고 exit 0

```
$ rarn cache clean < /dev/null
<cache 경로>
  1 packages, 2 files, 9 B
Delete all of it? (y/N) $ echo $?
0
```

지운 것은 없고, `nothing was deleted` 도 안 찍힌다. 그 줄은 `confirm()` **뒤**에 있는데
`confirm()` 이 영영 안 돌아오기 때문이다 — 입력이 이미 끝난 질문은 settle 하지 않고,
이벤트 루프가 마르면 프로세스가 0 으로 끝난다.

**RN-8 과 같은 문장으로 설명된다.** 그때 `init.ts` 에 적어 둔 주석이 그대로 여기 해당한다.
고친 곳은 하나였고 같은 모양을 가진 다른 하나는 그대로 남아 있었다.

**`init` 과 다르게 고쳤다.** `init` 은 기본값으로 진행한다. 여기는 거절한다.
비대칭이 분명하기 때문이다 — `init` 이 잘못 넘겨짚으면 사람이 고칠 수 있는 파일이 하나
생기고, 여기서 잘못 넘겨짚으면 이 기계의 모든 프로젝트가 다음 설치에 네트워크로 돌아간다.
CLAUDE.md 의 publish 절이 적어 둔 "두 방향의 값이 다르다" 와 같은 판단이다.

터미널에서 Ctrl+D 를 누른 경우는 **거절로 읽는다.** 답 없이 끝난 파괴적 질문에 대해
확실한 것은 하나뿐이다 — 아무도 예라고 하지 않았다.

### RN-15 — `--json` 만 조용했다

같은 캐시, 같은 불일치, 두 형식:

| | 본문 | 종료 코드 |
|---|---|---|
| 사람용 | `digest mismatch  @evaera/promise@4.0.0` | **1** |
| `--json` | `"mismatched": ["@evaera/promise@4.0.0"]` | **0** |

종료 코드를 세우는 줄이 JSON 분기의 `return` **뒤**에 있었다. `--json` 은 스크립트가 쓰는
형식이고 스크립트는 본문이 아니라 종료 코드를 읽으므로, 잡으라고 만든 호출자에게만
조용했다. 이 명령에서 유일하게 공격일 수 있는 발견이다.

**`doctor` 와 `outdated` 는 같은 자리를 옳게 갖고 있었다.** `doctor.ts` 는 JSON 분기 안에서
종료 코드를 세우고, `outdated.ts` 는 분기 밖에 둔다. 셋 중 하나만 틀렸다는 사실이 이것이
설계가 아니라 누락이었다는 증거다.

## 테스트가 스스로 거짓으로 통과했다

8개를 쓰고 전부 통과했다. **대조군을 돌리기 전까지는 그것이 아무 뜻도 아니었다.**

고치기 전 코드에 대고 돌렸더니 `--json` 테스트가 **통과했다.** 원인은 테스트 사이에
`process.exitCode` 가 샌 것이었다 — 앞 테스트(사람용 경로)가 1 로 두고 갔고, `afterEach` 의
복원이 듣지 않았다.

```
$ bun -e 'process.exitCode = 1; process.exitCode = undefined; console.log(process.exitCode)'
1
```

**Bun 1.3.14 에서 `process.exitCode = undefined` 는 초기화가 아니다.** `0` 을 넣어야 지워진다.

고친 뒤 대조군은 이렇게 나뉜다:

| 테스트 | 고치기 전 |
|---|---|
| `cache clean` 4개 | **멈춘다** — 답 없는 질문이 안 끝난다. 그 자체가 RN-14 의 증거 |
| `verify --json` | `Expected: 1  Received: 0` |
| 나머지 3개 | 통과 (이 셋은 회귀 방지용이지 결함 증거가 아니다) |

## 배운 것

**같은 결함을 두 번 만나면 그것은 결함이 아니라 자리다.** RN-8 을 고칠 때 `init.ts` 만
봤다. 그 결함이 "프롬프트를 가진 명령" 이라는 자리에 속한다는 것을 그때 세지 않았고,
그 자리에는 둘이 있었다. `grep -rn "createInterface" src/` 한 번이면 그때 끝났을 일이다.

**통과한 테스트는 대조군을 돌리기 전까지 아무 주장도 하지 않는다.** 이 마일스톤에서
가장 값싼 교훈은 결함 둘이 아니라, 그 둘을 잡으라고 쓴 테스트가 먼저 거짓으로 통과한
것이다. 감사가 찾으려던 실패 모드를 감사 자신이 재현했다.

**"안 본 것" 은 아직 유효했다.** 다만 남은 양은 적다 — 두꺼운 파일 여섯 중 결함은 한
파일에 몰려 있었고, 나머지는 실제로 배선과 출력이었다. CLAUDE.md 의 주장은 대체로 맞았고,
틀린 곳은 테스트가 하나도 없던 곳이었다.
