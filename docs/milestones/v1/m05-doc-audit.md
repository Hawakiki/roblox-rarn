## 왜 했나

1.0 은 포맷 동결이고, 그때부터 **문서도 약속이 된다.** 그런데 이 하루에만 세 개가 낡아
있었다 — README 가 404 를 가리켰고, place 파생 설명이 고정 파일명을 말했고, 하니스 호출에
`--mount` 가 빠져 있었다. 전부 우연히 발견됐다는 것이 문제였다.

## 낡아 있던 것 셋

**README 의 속도 표.** 콜드 `~1100 ms` 라고 적혀 있었는데 실측은 1877 · 1877 · 1964 ms 였다
(3회, 5 패키지). 네트워크 변동이 아니라 일관되게 1.7배다. `~1.9 s` 로 고치고, **콜드 수치는
대부분 네트워크라 읽는 사람 것이 아니라는 문장을 붙였다** — 주장할 값어치가 있는 것은 요청이
0인 웜 쪽이다. 웜은 `~45 ms` → 실측 52·53·55 ms 라 `~55 ms` 로.

**`exclude` 기본값 설명 두 곳** (README 와 CLAUDE.md). 둘 다 `.env`·`*.key`·`*.pem`·realm
디렉터리만 말하고 있었다. 같은 날 `_Index/` 를 가진 디렉터리도 제외하게 바뀌었는데(#29) 문서가
따라가지 않았다.

## 빠져 있던 것 둘

낡은 것이 아니라 **한 번도 적히지 않은 측정 사실**이다. CLAUDE.md 는 제약 권위이므로 이런
것이 여기 없으면 다음 사람이 같은 데 빠진다.

**Bun 과 Node 에서 라이브러리가 다르게 돈다** (RN-6). fflate 의 비동기 `unzip` 이 512 KiB
넘는 엔트리를 워커에 넘기는데 Bun 에서 그 워커가 아무것도 돌려주지 않는다. Bun 은 600,000
바이트에서 실패하고 500,000 에서 통과하며, Node 는 전 크기 통과다.

그냥 "출하 런타임으로 테스트하라" 로 끝내지 않았다 — 이 프로젝트는 **이미 Bun 으로 테스트를
돌리고 있었고 그래도 놓쳤다.** 픽스처가 그 경계를 넘지 않았기 때문이다. 그 사실까지 적었다.

**팬아웃에는 천장이 필요하고 그 곡선은 경사가 아니라 절벽이다.**

```
 8 -> 5.0s    16 -> 2.8s    32 -> 1.8s    64 -> 7.4s    무제한(150) -> 21.9s
```

무제한이 최적의 12배다. 해석이 그래프를 너비 우선으로 걷기 때문에 직접 의존 506개면 소켓
506개가 같은 순간에 열렸다. 메타데이터 32, 다운로드 8 — 몸통 크기가 달라 숫자가 다르고,
둘 다 취향이 아니라 측정으로 골랐다.

## 이 감사가 남긴 것

**대부분 맞았다.** 낡은 것은 셋이고 그중 둘은 같은 날 바뀐 코드를 문서가 못 따라간 것이다.
즉 문제는 문서를 안 쓴 것이 아니라 **코드와 같은 커밋에서 안 고친 것**이다. CLAUDE.md 는
Wally API 에 대해 이미 그 규칙을 갖고 있다 — *"update this file in the same commit as the
fix"* — 그것을 API 밖으로도 지켰어야 했다.

그리고 **기계적 검사는 값이 있었다.** 경로·코드·명령·식별자·링크는 사람이 읽어서 잡을
종류가 아니고, 스크립트로는 몇 초다. 다음 감사는 이 스크립트들로 시작하면 된다.
