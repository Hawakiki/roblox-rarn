# M7 — shim 이 타입을 전달하게

> 완료 시점의 사실만 담고 이후 편집하지 않는다 — 링크 수정만 예외.

**완료:** 2026-08-22
**결과:** 현장 프로젝트의 파사드가 필요 없어졌다. 설치 비용 +50ms.

---

## 왜 했나

[M6](m06-field-report.md) 의 현장 보고에서 **가장 오래 걸린 항목**이었다. 링크 shim 이
모듈의 **값**은 넘기고 **exported type alias 는 안 넘긴다.**

```lua
local React = require(ReplicatedStorage.Packages.React)
local function Cell(props: CellProps): React.Node   -- TypeError: Unknown type 'React.Node'
```

`React.createElement` 는 멀쩡히 체크된다. 타입만 안 넘어온다. `--!strict` 로 타입 있는
패키지를 쓰는 사람은 전원 만난다.

회피책이 둘 다 나쁜 것이 이걸 마일스톤으로 만든 이유다. `_Index["jsdotlua_react@17.2.1"]`
를 직접 require 하면 타입은 되지만 **버전 문자열이 앱 코드에 박히고**, 파사드를 쓰면
**패키지마다 손으로** 써야 한다. 현장 세션은 후자를 골랐고, 진짜 타입을 못 가져오니
`export type Node = any` 로 두었다.

**Wally 도 같은 구멍이 있다.** 결함 수정이 아니라 차별점이다.

## 크기

캐시 584패키지 기준: **300개(51%)가 엔트리에서 타입을 export**, 합 **1943개**.

| 패키지 | 타입 수 |
|---|---|
| `nightcycle/luau-math` | 118 |
| `jsdotlua/jest-types` | 90 |
| `jsdotlua/shared` | 45 |
| `jsdotlua/react` | 31 |

## 무엇을 만들었나

shim 이 한 줄이 아니게 됐다 — **타입을 export 하는 패키지에 한해서**.

```lua
-- Generated by Rarn. Do not edit; reinstalling overwrites this file.
local Module = require(script.Parent._Index["jsdotlua_react@17.2.1"]["react"])

export type Node = Module.Node
export type PureComponent<Props, State = nil> = Module.PureComponent<Props, State>

return Module
```

`src/linker/type-exports.ts` 가 엔트리 파일에서 `export type Name<params>` 헤더를 읽는다.
Luau 를 파싱하지 않는다 — 선언 헤더를 알아볼 만큼만 읽는다. 주석 제거는
`src/util/luau.ts` 로 옮겨 `doctor` 와 공유한다 (패키지는 Luau 로 자기를 문서화하므로,
문서 주석을 코드로 읽으면 둘 다 틀린다).

## 침묵이 실패 모드다

**이해 못 한 것은 추측하지 않고 뺀다.** 비대칭이 분명하다 — 빠뜨린 타입은 사용자가 어차피
손으로 쓰려던 주석 하나를 뺏는 것이고, 잘못 넘긴 타입은 **사용자가 쓰지도 않았고 고칠 수도
없는 파일에 에러를 넣는다.**

그래서 기본값이 패키지 내부 타입을 가리키면 **선언 전체를 버린다** — 패키지 안에서는
컴파일되고 shim 에서는 안 되기 때문이다. 그리고 그 버리기를 **고정점까지 반복한다**:
하나를 버리면 그것을 가리키던 다른 것이 고립된다.

허용되는 것은 셋뿐이다. Luau 내장 타입, 같은 모듈이 export 하는 타입(shim 이 그것도
재수출하므로), 그리고 같은 선언의 앞선 매개변수.

react 의 실제 두 사례가 여기서 갈린다:

```lua
export type PureComponent<Props, State = nil>            -- nil 은 내장 -> 통과
export type ReactElement<Props = Object, ElementType = any>  -- Object 도 export -> 통과
```

바인딩 이름도 조심해야 했다. `export type Module` 은 평범한 선언이고, 그러면 전달 줄이
전부 자기 자신을 가리키게 된다 — 이름이 겹치면 `RarnModule` 로 물러난다.

## 측정

**타입이 실제로 넘어오는가** — luau-lsp 로 확인. 같은 파일, 같은 프로젝트:

| shim | 결과 |
|---|---|
| `return require(...)` (전) | `Unknown type 'React.Node'`, `Unknown type 'React.Context'` |
| 타입 전달 (후) | **진단 0** |

**생성 트리 전체가 깨끗한가** — 52패키지 설치, shim 224개 중 **211개가 타입을 전달**한다.
`luau-lsp analyze` 를 `Packages` + `Packages_DEV` 전체에 돌려 **진단 0**.

**파사드가 정말 필요 없어졌는가** — 현장 프로젝트의 `Vendor/React.luau` 가 손으로 쓴
`export type Node = any` 를 갖고 있었다. 그것을 `= React.Node` 로 바꾸고 프로젝트
`src` + `tests` 전체를 분석: **진단 0**. 가짜 타입을 진짜로 갈아끼워도 통과한다.

**다른 생태계** — `test/game`(knit·comm·sift, 22패키지)에서 43개 shim 이 타입을 전달하고
Lune 하니스 52/52 통과.

**Lune 하니스** — `buildDiamond` 픽스처의 base 패키지가 이제 타입을 export 하므로, 중복
판정 검사가 여러 줄 shim 위에서 돈다. `export type` 이 `require` 의 반환을 바꾸지 않고,
특히 **한 인스턴스를 둘로 만들지 않는다**는 것이 실제 Luau 에서 확인된다.

## 비용, 그리고 처음에 잘못 낸 것

패키지마다 엔트리 파일을 하나 더 읽는다. 첫 구현은 **+225ms(60%)** 였다 — 52패키지 설치가
383ms 에서 607ms 로.

프로파일링해 보니 **파싱이 아니었다**: 엔트리 17개 85KB 를 strip + parse 하는 데 7ms.
전부 I/O 였고, 그것도 두 겹으로 잘못돼 있었다.

1. `pathExists` 로 `init.luau`/`init.lua` 를 **탐색**했다. 그런데 `pruneInto` 는 모듈이
   디렉터리인지 파일인지 **이미 안다.** 위에서 답한 질문을 아래서 다시 물은 것.
2. 그것을 설치 루프 **안에서 순차로** 했다. 서로 독립인 읽기 52개를 줄 세웠다.

`root.kind` 를 넘겨받고 루프 밖에서 32개씩 병렬로 읽게 고쳤다.

| | 시간 |
|---|---|
| M7 없음 | 383ms |
| M7 (첫 구현) | 607ms |
| M7 (고친 뒤) | **436ms** |

**+50ms (13%).** 처음 것을 그대로 냈으면 아무도 이유를 모른 채 설치가 느려졌을 것이다.

## 알면서 남긴 비용

**require 자체가 안 풀리는 곳에서는 진단이 늘어난다.** `Packages_DEV` 를 마운트하지 않는
소스맵으로 그 realm 을 분석하면, 전에는 `Unknown require` 하나였던 것이 전달하는 타입마다
하나씩 붙는다. 새로 깨진 것은 없다 — 그 require 는 원래도 안 풀렸다. 다만 한 줄이 여러
줄이 된다.

프로젝트가 자기 `Packages/` 를 분석에서 제외하는 것이 보통이라 실사용에서는 안 보인다.

## 배운 것

**성능 회귀는 짐작이 아니라 프로파일이 잡았다.** "파싱이 무겁겠지" 가 자연스러운 추측이고
7ms 로 틀렸다. 범인은 상위 계층이 이미 알고 있던 사실을 다시 물어본 것이었다.

**회피책의 존재가 요구사항이었다.** 현장 세션이 파사드를 쓴 것은 취향이 아니라 도구가 답을
안 줘서였고, 그 파사드를 지울 수 있는지가 이 마일스톤의 완료 조건이 됐다. 스스로 만든
기준이 아니라 실제로 막혔던 사람이 만든 기준이다.
