## "이거 왜 이렇게 만들었지"

거의 전부 [`CLAUDE.md`](../CLAUDE.md) 에 있고, **각 항목에 그렇게 정한 근거 측정값이 붙어
있다.** 915줄이라 절로 찾아가는 편이 빠르다.

| 궁금한 것 | 어디 |
|---|---|
| 왜 같은 패키지를 두 벌 깔면 안 되나 | 제약 1 — 중복은 정확성 결함이다 |
| `_Index` 와 shim 은 왜 이 모양인가 | 제약 2 |
| realm 이 왜 셋이고 왜 절대 경로가 필요한가 | 제약 2a |
| shim 파일을 왜 리졸버로 대체할 수 없나 | 제약 2a-2 |
| shim 이 왜 여러 줄이 됐나 (타입 전달) | 제약 2a-3 |
| 왜 매번 다시 짓고 마지막에 바꿔치기하나 | 제약 2b |
| `--offline` 이 왜 "보장" 인가 | 제약 2c |
| 왜 아카이브를 통째로 안 쓰고 가지치나 | 제약 3 |
| 패키지들이 왜 `:WaitForChild` 로 require 하나 | 제약 3a |
| Wally API 가 실제로 어떻게 동작하나 | 제약 4 — 라이브로 확인한 것 |
| 버전을 왜 이렇게 고르나 | 제약 5 |
| 계층이 무엇을 하고 무엇을 안 하나 | Architecture |
| 별칭·`_Index` 이름 규칙 | Naming |
| 락파일을 언제 재사용하나 | Reusing the lockfile |
| `RN####` 규칙 | Error codes |
| 브랜치 전략, 언어 정책, 커밋 규약 | Conventions |

## "이 결정 언제 왜 했나"

마일스톤 기록은 **완료 시점의 사실만** 담고 그 뒤로 동결된다. 측정값이 여기 있다.

- [`milestones/v1/`](milestones/v1/) — 1.0 을 향한 M1~M8. [색인](milestones/v1/README.md)
- [`archived/v0.1.0-v0.1.1/`](archived/v0.1.0-v0.1.1/) — 빈 디렉터리에서 0.1.1 까지, M0~M17.
  닫힌 시대라 그대로 둔다. [색인](archived/v0.1.0-v0.1.1/README.md)

**마일스톤 번호는 시대마다 M1 부터 다시 시작한다.** 같은 번호가 두 군데 있으므로 경로로
구분한다 — 아카이브의 M1 은 매니페스트, `v1/` 의 M1 은 라이브 발행이다.

동결된 기록이 틀린 것으로 드러나면 원문은 두고 날짜 붙은 **정정**을 덧붙인다. 고쳐 쓰지
않는다.

## 한 사실은 한 군데에만

같은 것을 두 문서가 말하면 반드시 갈라진다. 그래서 역할을 나눠 둔다.

| | 무엇을 담나 | 무엇을 안 담나 |
|---|---|---|

| `CHANGELOG.md` | 릴리스별 변경과 수정 상세 | 계획 |
| README | 쓰는 법 | 내부 사정 |
